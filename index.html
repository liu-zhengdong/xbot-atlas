XBot：新人导览

核对于 2026-10-17 0418c26
守护层 · 30 秒版主人确认后才改

XBot 是用 Go 从零写的个人 AI 助手，给一个主人在自己的机器上长期使用。交互单位是 Bot：一个有名字、有记忆、长期存在的实体，同一个主题只找一个 Bot，上下文一直连着，系统里没有"会话"。Bot 能在没人叫它时醒来，判断有没有值得告诉主人的事；能在授权的机器上做主人在终端里能做的事。终端和网页是同一条对话的两个入口。

守护层主人确认后才改

愿景与思想

已确认（2026-10-16，主人确认；最后一段 2026-10-17 更新，主人确认）。

Bot 是第三代交互模型。第一代是 Chat，第二代是 Session 和 Agent，第三代是 Bot：一个有记忆、长期存在的实体。主人不需要管理会话，也不需要 --resume；想聊哪件事，就去找负责这件事的那个 Bot。

Bot 有主动性。webhook、文件监听、其他 Bot、定时器都能唤醒它；它自己判断有没有值得说的事，有就说，没有就保持安静（回复 SILENT）。免打扰时段照样生效。主动性靠评测保证：看行为和结果，不看模型自己的汇报——自己设定目标，被打断后继续同一件事，做不到时停下来说明原因。

内核要薄，机制最小够用。不为特殊情况加规则，新能力尽量用已有的抽象（Link、Event、收件箱、执行器任务）表达。例如插话分叉的后台直接登记成执行器任务，确认规则收拢在一张权限表里。

Bot 是全能的。授权给它的机器，它能做主人在终端里能做的任何事。隔离靠部署方式，安全靠操作审核和保险箱，不靠假装能限制文件访问。

主人希望 Bot 任何时候都能在几秒内回应，哪怕它正忙着长任务，这一点靠「插话时分叉」做到了。现在在做的是对照 Claude Code 内部机制调研定下的 8 步内核计划：提醒通道与熔断、文件新鲜度、待办清单、shell 后台化、环境感知、搜索与看图、子代理类型、权限规则，前三步已经合入，第四步在做。同时三个 Bot 连续运行两周做验收，到 10-30 结束。再往后是开源网关、P2P 和跨用户通信。新想法先进 候选清单，不当场开工；计划和进度见 MILESTONES。

怎么配合

所有输入都变成 Event 进收件箱，每个 Bot 一个事件循环按顺序处理。一轮里内核组装上下文、调模型、把工具调用交给权限表审查后执行，所有结果只追加进 transcript。

走查：主人在网页上发一句「帮我看看这个 bug」。

  1. 网页 POST /api/bots/{name}/messages 接住（internal/web/server.go），认证后成为可信事件。
  2. 内核拿到处理锁，组装上下文：固定前缀（人设、规则、Link 说明）+ 摘要块 + 未压缩的尾巴 + 有变化时的环境更新（context.md）。
  3. 调用绑定的模型（internal/provider）；回复里的多个工具调用并行执行。
  4. 每个工具调用先过权限表和机器开关（security.md）；读文件、shell 读命令直接跑，删除或对外发送弹确认卡，卡片也写进 transcript。
  5. 结果按调用顺序追加进 transcript，SSE 流式回网页；轨迹进信息面板（ui.md）。
  6. 如果这一轮很长、主人又插了一句，这一轮分叉成后台继续，前台几秒内回答（fork.md）。

全局要求：性能与界面流畅

  • 链路不传大块数据：只传摘要或流式传输；每次节点调用上限 1 MiB，处处设大小上限。
  • 交互回复 p95 < 3 秒；本机进程间通信（IPC）额外开销 p95 < 5 毫秒；后台导致的变慢不超过 10%。
  • 界面：60fps；动画只动 transform/opacity，时长不超过 200 毫秒；遵守 prefers-reduced-motion；轮询不能引起重排、卡顿或抢焦点。
  • 每个里程碑验收都要报性能数字。

ADR 一览：0001 多个后台、0002 前台写操作自动排队、0003 一张权限表、0004 去掉主动性三档、0005 保险箱交给独立系统用户的守护进程。
